# Screen Bridge v1.1.0 Release Notes

Screen Bridge v1.1.0 packages the current Mac-to-iPad extended-display workflow
as a verified Universal Mac preview and aligns the Mac app, iPad receiver,
documentation, packaging scripts, Git tag, and GitHub Release on one version.

## Highlights

- Adds per-device audio routing for active Mac apps instead of a Chrome-only
  audio toggle.
- Keeps unassigned audio on the Mac and restores local output immediately when
  an iPad audio connection backgrounds, disconnects, or fails.
- Uses authenticated protocol v4 control messages in both directions with
  per-transport replay protection.
- Holds the Mac virtual display for up to five minutes while a backgrounded iPad
  reconnects, preserving window placement.
- Separates transport, video arrival, decoding, rendering, and audio health so
  one live signal cannot hide a failed media stage.
- Uses bounded video delivery, adaptive bitrate, timed AAC packets, and bounded
  receiver buffering to prevent delayed queues from growing without limit.

## Product and version identity

- Product name: `Screen Bridge`.
- GitHub repository: `ycl-2004/Screen-Bridge`.
- Git tag and release: `v1.1.0`.
- Mac and iPad bundle version: `1.1.0 (2)`.
- Mac asset: `Screen-Bridge-v1.1.0-macOS-universal.zip`.
- Internal `BetterCast*` targets, bundle IDs, Keychain IDs, and
  `_yc-cast._tcp` remain unchanged for compatibility.

## Mac download

The release ZIP contains `Screen Bridge.app` with both `arm64` and `x86_64`
slices. Its SHA-256 is:

```text
1e06b1b8c350094c26c70d094cac1411bd7d5ba50cc49ff342687efd4bb4bda7
```

The app is ad-hoc signed with Hardened Runtime and is not notarized. It is a
self-use/preview build. On first launch, Control-click the app, choose **Open**,
and confirm the prompt. A general public installer still requires Developer ID
signing and Apple notarization.

## iPad receiver

No IPA is published. The iPad receiver requires signing through Xcode with an
Apple Team and provisioning profile tied to the target device. A Personal Team
profile is short-lived and is not a public distribution mechanism.

## Verification

Observed on macOS 26.6.1 with Swift 6.3.3 and Xcode 26.6:

- `swift test`: 136 tests, 0 failures.
- Universal Release build: succeeded for `arm64` and `x86_64`.
- `codesign --verify --deep --strict`: passed for the packaged app.
- `unzip -t`: passed.
- Independently extracted ZIP: retained both architectures, `1.1.0 (2)` bundle
  metadata, and a valid ad-hoc signature.
- Unsigned generic iOS Release build: succeeded and produced an `arm64` app with
  `1.1.0 (2)` metadata.
- Mac/iPad plist validation, packaging script syntax, and `git diff --check`:
  passed.

The optional Swift 6.3 strict-concurrency warnings-as-errors check does not pass
because existing Core Audio/GCD closures still need complete `Sendable`
annotations. Standard Swift 5 language-mode builds and all tests pass.

## Known boundaries

- The Mac app is not Developer ID signed or notarized.
- Real-device post-package streaming, background recovery, and sustained audio
  listening were not repeated for this release build.
- No public iPad IPA is included.
- Video and audio are designed for trusted local networks and are not
  independently encrypted end to end.
- The K5 source-provenance question in the repository audit still needs
  owner/legal evidence before unrestricted public redistribution.
